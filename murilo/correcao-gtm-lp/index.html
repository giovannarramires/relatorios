As páginas de venda ainda estão com o código antigo do GTM

A troca feita hoje no site principal funcionou. Só que as páginas de venda do Manual do Prequestionamento ficam em outro endereço, o lp., e lá o código não foi trocado. Por isso, quem chega por anúncio não está sendo medido.

Conferido em 27/10/2026 · contêiner GTM-5PW9JMJT

Quais páginas

https://lp.profmurilosoares.com.br/trocar
https://lp.profmurilosoares.com.br/v2-sb/trocar
https://lp.profmurilosoares.com.br/v3/trocar

Estas são as páginas para onde os anúncios de venda estão levando hoje. O site principal (profmurilosoares.com.br, incluindo /irrp-inscricao/ e /obrigado/) já está certo e não precisa de nada.

O que está acontecendo

As 3 páginas carregam o GTM por um endereço que não funciona mais. No código delas está assim:

j.src="https://api.profmurilosoares.com.br/2hihhwiaauu.js?"+i;
…
<iframe src="https://api.profmurilosoares.com.br/ns.html?id=GTM-5PW9JMJT" …>

O endereço api.profmurilosoares.com.br responde com certificado de segurança inválido e "página não encontrada" (erro 404). O navegador bloqueia, e o GTM nunca chega a rodar. Com isso, nessas páginas não dispara:

  • o Pixel da Meta: a visita na página e a ida para o checkout
  • o Google Analytics 4
  • o Microsoft Clarity

Por que isso importa

  • Os anúncios aprendem com menos informação. A Meta só fica sabendo da compra (que chega pela Ticto) e não vê quem visitou a página nem quem foi para o checkout. Com menos sinal, ela demora mais para achar quem compra.
  • O remarketing perde gente. Quem visitou a página de venda e não comprou não entra no público de visitantes, que é o público mais quente para anunciar de novo.
  • Não dá para comparar as páginas. Sem medir visita e checkout em cada versão (raiz, v2-sb e v3), não dá para saber qual converte melhor.

As vendas continuam sendo registradas pela integração da Ticto. Por isso o problema não aparece de cara.

O que fazer

  1. Abrir as 3 páginas no editor do lp.

    O lp. não é o mesmo WordPress do site principal, por isso a troca de hoje não chegou até ele. A troca tem que ser feita onde essas 3 páginas são editadas. Se o código estiver num cabeçalho comum às 3, basta trocar uma vez.

  2. No <head>: apagar o bloco antigo e colar este

    Apague o script que tem api.profmurilosoares.com.br/2hihhwiaauu.js e cole no lugar exatamente o código abaixo. Use o botão para copiar, não passe pelo WhatsApp.

    <!-- Google Tag Manager -->
<script>(function(w,d,s,l,i){w[l]=w[l]||[];w[l].push({'gtm.start':
new Date().getTime(),event:'gtm.js'});var f=d.getElementsByTagName(s)[0],
j=d.createElement(s),dl=l!='dataLayer'?'&l='+l:'';j.async=true;j.src=
'https://www.googletagmanager.com/gtm.js?id='+i+dl;f.parentNode.insertBefore(j,f);
})(window,document,'script','dataLayer','GTM-5PW9JMJT');</script>
<!-- End Google Tag Manager -->

  3. Logo depois do <body>: trocar o noscript

    Apague o <noscript> que aponta para api.profmurilosoares.com.br/ns.html e cole este:

    <!-- Google Tag Manager (noscript) -->
<noscript><iframe src="https://www.googletagmanager.com/ns.html?id=GTM-5PW9JMJT"
height="0" width="0" style="display:none;visibility:hidden"></iframe></noscript>
<!-- End Google Tag Manager (noscript) -->

  4. Limpar o cache e conferir

    Abra cada uma das 3 páginas, clique com o botão direito › Exibir código-fonte e procure (Ctrl+F):

    • api.profmurilosoares: não pode aparecer
    • googletagmanager.com/gtm.js: tem que aparecer 1 vez, sem colchetes

  5. Avisar a GGD

    A gente confere as 3 páginas e testa se a visita e a ida ao checkout estão chegando na Meta e no GA4.

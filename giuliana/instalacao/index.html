Instalação do GTM, do pixel e do GA4

Hoje a LP e o checkout não têm nenhum código de rastreamento: o Meta não recebe nem visita nem compra, então não dá para otimizar campanha por conversão nem montar público de remarketing. Este é o passo a passo para ligar tudo. As tags já estão montadas e publicadas — falta colar o container na página e configurar o checkout.

1 Colar o GTM na LP (Vercel)

A página www.giulianamarketing.com.br é um HTML estático publicado na Vercel. Abra o arquivo index.html do projeto e cole os dois trechos abaixo.

A) logo depois da tag <head>, o mais alto possível:

<!-- Google Tag Manager -->
<script>(function(w,d,s,l,i){w[l]=w[l]||[];w[l].push({'gtm.start':
new Date().getTime(),event:'gtm.js'});var f=d.getElementsByTagName(s)[0],
j=d.createElement(s),dl=l!='dataLayer'?'&l='+l:'';j.async=true;j.src=
'https://www.googletagmanager.com/gtm.js?id='+i+dl;f.parentNode.insertBefore(j,f);
})(window,document,'script','dataLayer','GTM-W3TGGSDG');</script>
<!-- End Google Tag Manager -->

B) logo depois da tag <body>:

<!-- Google Tag Manager (noscript) -->
<noscript><iframe src="https://www.googletagmanager.com/ns.html?id=GTM-W3TGGSDG"
height="0" width="0" style="display:none;visibility:hidden"></iframe></noscript>
<!-- End Google Tag Manager (noscript) -->

Depois é só fazer o deploy. Com isso, a LP passa a disparar PageView e ViewContent no pixel, InitiateCheckout quando alguém clica no botão de compra, e o GA4 de tráfego — tudo já configurado dentro do container.

2 Pixel + CAPI no checkout da Hubla

O checkout pay.hub.la/tPsBe5j64aEwb9HflhJn está sem pixel. Na Hubla, o rastreamento fica no produto, não na página de vendas:

  1. Entrar na Hubla → produto Mapa da Criação de Conteúdo para Dentistas → aba Pixels de Rastreamento.
  2. Adicionar o pixel 260219322254560 e colar o token de CAPI (gerado no Gerenciador de Eventos do Meta, em Configurações do conjunto de dados → API de Conversões).
  3. Nos eventos, usar a “Recomendação da Hubla”: ViewContent, InitiateCheckout (ao começar a preencher), AddToCart (order bump) e Purchase (só aprovado, valor total pago).
  4. Salvar e conferir se aparece “Pixel editado com sucesso”.

Sem esse passo não existe evento de compra — e sem compra o Meta não tem o que otimizar.

3 Anunciar direto no checkout, com UTM

Atenção: a LP não repassa utm_* nem fbclid para o checkout — o botão de compra é um link fixo. Se o anúncio mandar para a LP, não dá para saber qual criativo vendeu.

Enquanto o link não for corrigido, os anúncios de venda devem apontar para o checkout já com as macros:

https://pay.hub.la/tPsBe5j64aEwb9HflhJn?utm_source=meta&utm_medium=paid&utm_campaign={{campaign.name}}&utm_content={{ad.name}}&utm_term={{adset.name}}

Alternativa melhor no médio prazo: ajustar o botão da LP para repassar a query string, aí o anúncio pode ir para a página de vendas sem perder a origem.

4 Conferência depois de publicar

  • Abrir a LP e ver se o Gerenciador de Eventos do pixel 260219322254560 registra PageView e ViewContent.
  • Clicar no botão de compra e confirmar o InitiateCheckout.
  • Fazer uma compra de teste para validar o Purchase pela CAPI da Hubla (é o único jeito, o evento sai do servidor).
  • No Gerenciador de Eventos, checar a lista de permissão de domínios do pixel: se estiver ativa, incluir giulianamarketing.com.br e pay.hub.la, senão o evento de navegador é descartado.
  • No GA4, ver o relatório Tempo real com a visita de teste.

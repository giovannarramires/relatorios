Guia de instalação — Google Tag Manager, Pixel da Meta e GA4

Documento para quem cuida do código da página. Hoje a landing page e o checkout não têm nenhum código de rastreamento instalado: nenhuma visita, nenhum clique e nenhuma compra chega ao Meta ou ao Google. Sem isso não é possível otimizar campanha por compra nem montar público de remarketing.

O container do GTM, o pixel e o GA4 já estão criados e publicados — as tags estão prontas dentro do container. O que falta é colar dois trechos de código na página e fazer um pequeno ajuste no botão de compra. Leva menos de 15 minutos.

2 Fazer o botão de compra repassar a origem do anúncio

o que o desenvolvedor faz · obrigatório
Problema atual: o botão “Quero garantir” aponta para um link fixo do checkout. Quando alguém chega pelo anúncio com ?utm_source=...&fbclid=..., esses parâmetros morrem no clique — o checkout não recebe nada e fica impossível saber qual anúncio gerou a venda.

A correção é copiar a query string da página para os links do checkout. Cole este trecho antes do fechamento do </body>:

<script>
(function(){
  function repassarParametros(){
    var qs = window.location.search;
    if (!qs || qs.length < 2) return;
    var params = qs.substring(1);
    var links = document.querySelectorAll('a[href*="pay.hub.la"]');
    for (var i = 0; i < links.length; i++) {
      var href = links[i].getAttribute('href');
      if (href.indexOf('utm_') !== -1) continue;
      links[i].setAttribute('href', href + (href.indexOf('?') !== -1 ? '&' : '?') + params);
    }
  }
  if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', repassarParametros);
  } else {
    repassarParametros();
  }
})();
</script>

Depois disso, abrir www.giulianamarketing.com.br/?utm_source=teste, clicar no botão e conferir se o ?utm_source=teste chegou na URL do checkout.

3 O funil completo — onde cada evento nasce

referência · nada a fazer aqui

A otimização das campanhas é por compra, então o funil precisa estar inteiro: visita → conteúdo visto → intenção de compra → checkout iniciado → compra. Metade dos eventos sai da página (via GTM) e a outra metade sai do checkout da Hubla — é assim porque o checkout roda em outro domínio, onde o nosso GTM não é carregado.

Por isso o InitiateCheckout não é disparado pela página: quem dispara é a Hubla, quando a pessoa realmente começa a preencher o formulário. Se a página também mandasse, o evento seria contado duas vezes e a otimização ficaria distorcida.

4 Pixel e CAPI dentro da Hubla

quem tem acesso ao painel da Hubla
  1. Hubla → produto Mapa da Criação de Conteúdo para Dentistas → aba Pixels de Rastreamento (não é em Configurações).
  2. Adicionar o pixel 260219322254560.
  3. Colar o token da API de Conversões, gerado no Gerenciador de Eventos da Meta → conjunto de dados do pixel → Configurações → API de Conversões → “Gerar token de acesso”.
  4. Em eventos, usar a “Recomendação da Hubla”: ViewContent, InitiateCheckout (ao começar a preencher), AddToCart (order bump) e Purchase (somente aprovado, valor total pago).
  5. Salvar e conferir a mensagem de sucesso.

Sem esse passo não existe evento de compra — e sem compra o Meta não tem por onde otimizar.

5 Conferência depois de publicar

checklist final
  • Abrir a página e confirmar, no Gerenciador de Eventos da Meta, o PageView e o ViewContent chegando no pixel 260219322254560.
  • Clicar no botão de compra e ver o AddToCart aparecer.
  • Conferir se a URL do checkout chegou com os parâmetros utm_*.
  • Fazer uma compra de teste — é a única forma de validar o Purchase, porque ele sai do servidor da Hubla.
  • No pixel, checar a lista de permissão de domínios (Gerenciador de Eventos → Configurações do conjunto de dados → Permissões de tráfego). Se estiver ativa, incluir giulianamarketing.com.br e pay.hub.la, senão os eventos do navegador são descartados sem aviso.
  • No GA4, ver a visita de teste no relatório Tempo real.

Resumo do que precisa ser feito na página: colar o GTM no <head> e no <body> (passo 1) e adicionar o script que repassa a query string para o checkout (passo 2). É só isso do lado do código — todo o resto do rastreamento é configuração e já está pronto ou é feita no painel da Hubla.
